# Reviewed savings material fields

New interpreter jobs use terms-parameters-v3 and analysis-staging-material-v1.
The context binds the canonical staging schema SHA. Retained v1/v2 contexts and
their registry hashes remain unchanged; scalar description revisions do not
authorize new monetary policy publication.

Each structured revision binds one of 17 closed field projections, exact product,
cohort, tier and package scope, and a dated interval. Source verification requires
matching reviewed values for each actual field-coverage clause and used interval.
Adjacent matching intervals may jointly cover a span. Policy provenance hashes
are excluded from material values to avoid identity cycles; semantic tier, rule,
input, allocation, rounding and absence declarations are retained.

The worker derives a separate strict-output generation schema. It specializes
optional scope fields to the validated job context and uses closed discriminated
unions. Unsupported negative assertions and array uniqueness are generation
guidance omissions only: the original canonical schema and semantic validators
still enforce them before staging. The worker binds the generated schema bytes
in the lease receipt and verifies them on completion. No provider call is needed
to test the generated dialect; provider availability is not source approval.

Historical technical captures remain immutable. The new connected-material
fixture proves the controller protocol using explicitly synthetic engineering
policy, not approval of any bank product or historical source.
