# Held optional evidence dispatch

This source is not commissioned. Both existing delivery flags default to `0`.
There is no new timer, automatic flag change, queue claim, source activation,
credential installation, or retrospective claim about a financial publisher.

## Financial first

After a verified financial publication, `pi_daily_sync` may create an immutable
optional request. It binds the current source pointer bytes, original committed
publication/index, financial asset hashes, enabled lanes, and clean writer
commit/tree. An enqueue failure is reported without reversing financial success
or preventing terminal backup. The source-key mapping never rebinds an existing
request when flags, code, or available packages change.

The request's private financial projection removes optional status/references
only. Its retained parent revision metadata does not make this projection a
selected edition. A later optional publication receives a new revision through
the existing transaction, with an exact published predecessor check.

## Existing opportunities and finite stages

Only an otherwise healthy existing watchdog invocation attempts work, after
capture, financial retry, and continuity work. Natural capture enqueues only.
Missing commissioned launcher/profile explicitly defers. Each opportunity
borrows its executing AR-only exclusive claim; it acquires no second queue
claim or host lease. Publication's ordinary parent acquires one native-format
production lease, refusing every existing owner, and retains its descriptor.

Stages are `snapshot`, enabled `facts`/`responses`, `delivery`, and `publish`.
Each uses a new private attempt directory under backed-up state. Only a
committed result hash can feed the next stage. An interrupted uncommitted output
is retained and never discovered as a replacement source. Eight attempts per
stage and bounded cooldown apply; ambiguous worker cleanup blocks reuse.

The absolute allowance is the minimum of 1800 seconds, the conservative original
parent allowance, and the original Hobart 00:30 cutoff, reserving 45 seconds for
cleanup. Rechecks cannot renew it. Existing aggregate memory observation,
CPU/process limits and early-stop rules remain; configured cgroup memory values
are not proof that the host kernel supports hard aggregate memory enforcement.

Private owned attempt storage has a 2 GiB/20,000-entry ceiling, with 8 GiB free
space and 4096 free inodes required. Retained failures count. Incremental checks
are followed by a complete bounded terminal scan before a passing receipt.
These bounds are held qualification limits, not evidence that the expanded
current capture fits. Exhaustion fails explicitly without truncating facts or
deleting earlier evidence. No automatic retention cleanup is introduced.

## Privileged boundary and installation

`pi_product_evidence_launch.py` is a standalone standard-library helper at one
fixed root-owned path. Its root-protected profile binds the ordinary account,
exact source commit/tree and complete source/runtime inventories. Every ancestor
and imported candidate file must be protected; no writable checkout is imported
as root. The materialized interpreter/runtime is independently commissioned,
including its host Python/library dependency provenance. This source does not
build or install that runtime or qualify a substituted host dependency.

The caller supplies opaque request/attempt IDs and the existing owner proof,
never executable paths, arbitrary arguments, environment or mount settings.
The launcher independently checks queue/native parent identity and binds the
ordinary child to that parent. Preparation has no network or credentials.
Publication is a distinct phase with PID1 loading one fixed, hash-pinned
credential file. All writable locations are fixed state/attempt paths.
The state parent and production lock remain read-only inside the child. Root
and child verify the parent's exact live PID/start/boot/cgroup, descriptor,
named inode and manual-recovery record. There is no general lock bypass for
ordinary callers. Parent release requires verified terminal child cleanup;
unknown cleanup or parent death retains an explicit manual recovery obligation.

`pi_product_evidence_install.py` may run only as externally hash-pinned bytes in
a protected stage, under an existing AR+host claim. Its explicit plan and exact
CI/qualification receipt bytes are independently reviewed operator inputs. It
changes only the launcher, profile and fixed sudoers definition. Check/apply/
rollback have a 240-second whole-process bound inside a 300-second claim.
Preimages, partial failures and readbacks remain durable. Rollback refuses a
foreign postimage and may use a new admitted claim. No service or timer is
started, stopped or enabled. Definition installation does not enable flags.

The ordinary private-directory helper preserves ownership/privacy checks, but
is not descriptor-atomic against hostile same-user ancestor replacement. The
privileged profile/staging boundary instead requires root-owned ancestry.

## Completion and remaining acceptance

Root terminal evidence binds worker/result/resource hashes and an empty owned
group. Publication completion separately binds the exact new writer commit,
tree, code/runtime/profile hashes, selected revision and retained promotion.
It records the original financial writer as unknown. Interrupted own-child
selection can finish aliases using the existing exact predecessor lineage
proof; a different current head is not silently adopted.

Local captured-fixture tests do not establish commissioning. Before enabling,
require actual expanded-source normalized/raw pack measurements, complete
recursive inventory and app audit, largest-product controls, root helper/runtime
qualification, parent-death/cleanup checks, source supersession and retry
proofs, public encrypted readback and the applicable backup/restore acceptance.
No UI rendering, population completeness, original-wire completeness or Drive
acceptance is inferred from these dispatch receipts.
